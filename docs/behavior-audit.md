# Проверка поведения свитчера

Проверка от 13 ноября 2026 года. Изучены ядро, перехват клавиатуры, вставка текста,
выделение, переключение раскладки и существующие незакоммиченные изменения.

## Ожидаемое поведение

- Автоматически исправлять только распознанные слова; сохранять правильный текст,
  числа, адреса, пути и код.
- По ручной команде исправлять ошибочные слова во фразе; если таких нет — последнее
  слово. Повторная команда возвращает последнюю замену, пока пользователь не продолжил ввод.
- Удалять ровно заменяемый хвост, сохраняя текст слева и пробелы справа.
- Чистые знаки инвертировать только вручную, с учётом текущей раскладки. Для ABC / «Русская»:
  `:` → `%` из русской; `%` → `:` из английской; `%` → `$` из русской.
- Не применять запоздавшее действие к другому полю или приложению.

## Найденные ошибки и исправления

| Сценарий | Причина | Исправление |
| --- | --- | --- |
| `b` → пробел → Backspace → пробел → `ghbdtn` → пробел | Отложенное слово осталось в памяти; повторная запись создавала неправильные диапазоны и падение | Удаление разделителя снимает отложенное решение; диапазоны дополнительно проверяются |
| `ghbdtn` → немедленная ручная инверсия; снимок экрана ещё `ghbdt` | Память укорачивалась до пяти букв; удаление оставляло `g` перед заменой | Недавно набранное слово сохраняется при отставании снимка |
| Backspace → немедленная инверсия | Снимок может ещё содержать уже удалённые буквы | Сразу после удаления используем память ввода, не старый снимок |
| Одиночный `:`, выделенное `99:`, десятичное `50,5:` | Конвертер требовал букв; частный случай поддерживал лишь целое число | Направление знаков определяется исходной раскладкой; цифровая часть сохраняется |
| `"ghbdtn"` | Парные кавычки превращались в русские буквы | Парное обрамление сохраняется при преобразовании слова |
| Акцент отдельным событием после `e` | В памяти два элемента, на экране один составной символ | После ввода пересчитываются видимые символы; неизвестный предшествующий символ не затрагивается |
| Новый ввод / смена поля во время резервного копирования выделения | Результат применялся спустя 150 мс без проверки контекста | Проверяются версия ввода, приложение, фокус, выделение, активность и защищённый ввод |
| Новое копирование во время ожидания | Старый буфер восстанавливался поверх нового | Отменённая операция не восстанавливает буфер |
| Быстрая смена раскладки после исправления | Старый отложенный повтор выбирал предыдущую раскладку | Повторы привязаны к актуальному запросу и отменяются после подтверждённой смены |
| Ручная команда в новой программе без обычного набора | Цель не запоминалась; повторная команда сбрасывала отмену | Цель обновляется и при ручной команде |
| Пропуск событий после отключения перехвата macOS | Модель продолжала считать старый текст актуальным | При восстановлении перехвата память сбрасывается |
| Быстрый набор во время автоисправления | Синтетические события возвращались в начало системного потока | Внутри перехватчика события отправляются дальше через его proxy |

Причина дубля воспроизведена на уровне планирования удаления; воспроизведение именно
пользовательского сбоя в конкретной программе пока не выполнено.

## Автоматические проверки

```sh
swift run core-tests
./scripts/test-keyboard.sh
```

`BehaviorAuditTests.swift` добавляет проверки знаков, кавычек, отмены, отложенных слов,
Unicode и устаревших снимков. Двадцать фиксированных последовательностей по 400 действий
проверяют главное условие: удаляемый текст действительно находится перед курсором.
Правильные слова, числа, код и адреса проверяются во всех пяти категориях приложений.

Нативный скрипт проверяет смену цели, повторную отмену, удаление составных символов
в `NSTextView` и восстановление нескольких форматов отдельного тестового буфера.
Он не посылает глобальных событий и не использует личный буфер обмена.

Результат: в рабочей версии прошли 109 тестов в 18 наборах; в отдельной копии
подготовленных коммитов без незавершённых пользовательских изменений — 108 тестов.
Сборка приложения и нативные проверки завершились с кодом 0.

Системные словари требуют доступа к сервисам macOS: ошибки XPC в песочнице делают
результаты орфографических тестов недостоверными. Новые сценарии используют фиксированный словарь.

Реальные источники ввода проверены только чтением: `com.apple.keylayout.ABC` и
`com.apple.keylayout.Russian`. Их системная карта полностью совпала с `macRussian`.

## Проверки в реальных приложениях — ещё не выполнены

Уточнение пользователя: лишняя первая буква и неработающая инверсия возникают в поиске
Launchpad. В коде выявлен дополнительный путь: ручная команда сверяла получателя ввода
с `frontmostApplication`, хотя системная панель может получать клавиши поверх другого
активного приложения. Из-за этого терялась память запроса, а Accessibility мог читать
поле фонового приложения. Теперь получатель берётся из события команды; известный
получатель набора сохраняется, если событие не сообщает PID и активное приложение
не менялось. Чтение Accessibility
ограничено тем же процессом. Обычная смена приложения по-прежнему сбрасывает память.
Контекст и исключения восстанавливаются по получателю следующего обычного нажатия,
даже когда закрытие панели не вызывает отдельного уведомления активации.

Нативный тест воспроизводит различие получателя поиска и активного фонового окна,
проверяет инверсию, отмену и владельца AX-элемента. Проверить именно пользовательский
случай вживую не удалось: автоматизация окон macOS вернула тайм-ауты. Это исправление
выявленного пути в коде, а не подтверждение исчезновения симптома в Launchpad.
Не проверен случай: панель закрылась без уведомления активации, а следующая команда
сообщает PID 0 до нового обычного ввода. Этих данных недостаточно, чтобы отличить
закрытую панель от открытой; необходима проверка реальной доставки событий.

Запускать на тестовом тексте после запуска сборки с исправлениями. Повторять в TextEdit,
браузерном поле, чате, терминале и редакторе кода; сохранность текста слева обязательна.

| Действия | Ожидаемый результат |
| --- | --- |
| Быстро `ghbdtn rfr ltkf `; затем ещё одно слово без паузы | `привет как дела `; ни дублей, ни потерь следующего слова |
| `ghbdtn` → сразу Option, повторить 20 раз с разной скоростью | Только `привет`, без оставшегося `g` |
| `ghbdtnn` → Backspace → сразу Option | `привет`; текст слева не удалён |
| Русская раскладка: Shift+5 → Option | `%`; повторный Option возвращает `:` |
| `скидка 50,5:` → Option | `скидка 50,5%` |
| Исправить слово → несколько раз Option → дописать слово | Переключение туда-обратно; после нового ввода старая отмена недоступна |
| Исправить → вручную сменить раскладку менее чем за 50 мс | Старый повтор не возвращает предыдущую раскладку |
| Выделить несколько строк с последним Enter → Option | Замена с сохранением перевода строки, если выделение подтверждается Accessibility |
| В редакторе без поддержки Accessibility: выделить → Option → сразу перейти в другое окно | Ничего не вставляется в новое окно |
| Во время ожидания резервного копирования нажать Cmd+C | Новый пользовательский буфер не затирается |
| Option+Space, Option с dead key, Shift+знак, Caps Lock | Системный ввод сохраняется; символы слева не повреждаются |
| Стрелка / клик в середину слова → дописать хвост → пробел | Хвост не исправляется как самостоятельное слово |
| Включить другую раскладку или защищённое поле | Автоматическая и ручная конверсия не вмешиваются |
| Автоисправление macOS, типографские кавычки, точка после двух пробелов | Проверка экрана сохраняет подходящее исправление либо безопасно отказывается |

## Ограничения проверки

Модель и AppKit не доказывают доставку глобальных событий в сторонние редакторы.
Именно поэтому таблица выше не отмечена как пройденная. При отмене резервного копирования
его временно скопированный текст может остаться в буфере: восстановление пропускается,
чтобы не затереть новое пользовательское копирование.

Если редактор не сообщает ни текст, ни диапазон выделения, нельзя надёжно отличить
выделение с последним Enter от команды «копировать текущую строку». В этом случае
сохраняется отказ от преобразования такого результата. Поддерживается только пара
источников ввода, для которой построена карта, а не любые раскладки того же языка.

Перехват клавиатуры и резервное чтение через буфер затрагивают личный ввод — нужен взгляд инженера.
