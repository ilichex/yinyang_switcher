# Repository Guidelines

## Структура проекта

YinYang — переключатель русской и английской раскладки для macOS 14+. Проект использует Swift Package Manager и Swift tools 5.10.

- `Sources/SwitcherCore/` — определение языка, преобразование раскладки, состояние ввода, обучение и сочетания клавиш. Изменения алгоритмов размещайте здесь.
- `Sources/YinYangSwitcher/` — приложение: перехват клавиатуры, вставка текста, выбор раскладки, меню и обновления.
- `Tests/SwitcherCoreTests/` — проверки логики и сценарии набора текста.
- `Resources/` — `Info.plist` и иконка приложения; `scripts/` — сборка, подпись и упаковка DMG.
- `docs/` — графика и материалы ролика. `.build/` и `build/` содержат результаты сборки.

## Сборка, тесты и локальный запуск

Команды выполняйте из корня репозитория на Mac с установленными Command Line Tools:

```sh
swift build --product YinYangSwitcher # Проверить сборку приложения
swift run core-tests                 # Запустить тесты логики
./scripts/build-app.sh               # Собрать build/YinYang.app
open build/YinYang.app               # Запустить приложение
```

Скрипт сборки пересоздаёт пакет приложения и вызывает подпись. Для ручной проверки перехвата клавиатуры приложению нужен доступ в разделе «Универсальный доступ» macOS.

## Стиль кода и именование

Используйте четыре пробела для отступов. Типы и файлы называйте в `UpperCamelCase`, функции и свойства — в `lowerCamelCase`. Следуйте стилю соседнего кода; отдельный форматтер или линтер не настроен. Комментарии пишите кратко, по-русски, объясняя неочевидную логику. Сохраняйте разделение алгоритмов и интеграции с macOS.

## Проверка изменений

Тесты используют Swift Testing: `@Suite`, `@Test`, `#expect`. Запускайте `swift run core-tests`: тесты оформлены как исполняемая цель, поэтому обычный `swift test` здесь не является командой проверки. Имена тестов должны описывать поведение, например `correctWordsStay`. Добавляйте сценарии для исправления, отмены и сохранения правильного текста. Численный порог покрытия не задан. Изменения клавиатурной интеграции дополнительно проверяйте вручную.

## Коммиты и pull request

В истории используются короткие русские сообщения: `YinYang 0.2.7: хвосты слов и выделенный текст`. Пишите конкретно, что изменилось; версию указывайте при релизных изменениях. Делайте отдельный коммит на завершённый рабочий шаг. В PR укажите проблему, новое поведение, связанные issues при наличии и результаты проверок. Для изменений меню или значка приложите скриншот.

## Безопасность

Не сохраняйте набранный текст в логах. Не добавляйте секреты и сертификаты в Git. Учитывайте существующее локальное хранение обучения в `~/Library/Application Support/YinYang/learning.json`. Проверяйте `git status` и включайте в коммит только файлы своей задачи.
